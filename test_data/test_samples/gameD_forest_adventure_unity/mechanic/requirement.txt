# Mechanic Code Generation Requirements — gameD_forest_adventure_unity

## 概述

本目录包含 gameD_forest_adventure_unity（自由探索 ARPG）的游戏机制代码生成任务。
通过 LLM Agent 调用 Unity 工具链自动生成 C# 脚本、创建游戏对象、绑定动画、编译验证。

---

## 生成方式

Agent 接收以下上下文后自主规划工具调用：
- 游戏设计文档
- 引擎 API 参考文档
- 资产清单（prefabs, animations, scenes, VFX）
- 验收清单 (acceptance checklist)

然后按以下流程执行：
```
Requirement → LLM Agent receives context → Plans tool calls →
Execute tools → Compile → Run playmode → Validate → Repair (if needed)
```

---

## 引擎与 API

- **引擎**: Unity3D 2022.3 LTS (URP)
- **engine_api_docs**: agent_skills/engine_context/unity3d_api.md
- **输出**: Unity Assembly (C# DLL) + C# 源码

## Static Preview / Motion Late Binding

The first Unity preview is assembled before generated motion is available.
For this milestone, the hero, bat, goblin, weapons, props, and forest scene
must still be imported and the complete exploration, combat, enemy, treasure,
camera, and UI logic must run. Animator controllers and animation clips are
optional: when absent, keep imported models in their source static poses and
drive player/enemy locomotion from their root controllers.

Melee/ranged attack timing, damage, death state, chest interaction, projectiles,
and UI updates must not depend on animation events. Do not generate fake
animation files. Keep named animation binding slots so later retargeted FBX
clips can be attached without regenerating or rewriting the core mechanic
assembly.

## 可用工具 (Tools)

| 工具 | 说明 |
|------|------|
| unity.create_script | 创建 C# 脚本文件 |
| unity.create_gameobject | 创建游戏对象 |
| unity.add_component | 为对象添加组件 |
| unity.bind_animation | 绑定动画片段到角色 |
| unity.create_animator_controller | 创建 Animator Controller |
| unity.assign_prefab | 分配 Prefab 引用 |
| unity.create_input_action | 创建 Input System 动作 |
| unity.set_physics | 设置物理参数（Rigidbody, Collider） |
| unity.create_tag | 创建 Tag 和 Layer |
| unity.compile | 编译项目 |
| unity.run_playmode | 运行 Play Mode |
| unity.screenshot | 截图验证 |
| unity.read_log | 读取运行日志 |

## 机制类清单

### 1. AdventurePlayerController (demoForest_043)
- **职责**: 第三人称角色控制（移动、跳跃、攻击切换）
- **输入**: 弓手角色 prefab, 动画集 (idle/walk/run/jump/...), 输入系统
- **输出**: AdventurePlayerController.cs
- **验证**: 角色可移动、跳跃、动画播放正确

### 2. CombatSystem (demoForest_044)
- **职责**: 近战挥剑 + 远程射箭战斗逻辑
- **输入**: 角色控制器, 剑/弓动画, VFX 资产, 音效
- **输出**: CombatSystem.cs
- **验证**: 左键挥剑、右键射箭、命中判定正确

### 3. BowAimingSystem (demoForest_045)
- **职责**: 弓箭瞄准模式（按住右键进入瞄准，松开发射）
- **输入**: 摄像机控制器, 单段远程攻击动画 (ranged_attack), 准星 UI
- **输出**: BowAimingSystem.cs
- **验证**: 右键进入瞄准、准星显示、松开发射

### 4. ProjectileSystem (demoForest_046)
- **职责**: 光箭弹道物理、碰撞检测、伤害结算
- **输入**: 光箭 prefab, VFX 粒子拖尾, 音效
- **输出**: ProjectileSystem.cs, LightArrow.cs
- **验证**: 光箭飞行、碰撞命中、粒子拖尾

### 5. EnemyAI (demoForest_047)
- **职责**: 蝙蝠飞行追击 + 哥布林地面追击 AI 行为
- **输入**: 蝙蝠/哥布林 prefab, 动画集, NavMesh, 玩家引用
- **输出**: EnemyAI.cs, BatAI.cs, GoblinAI.cs
- **验证**: 蝙蝠飞行追击、哥布林地面追击、攻击行为

### 6. EnemySpawner (demoForest_048)
- **职责**: 怪物刷新点管理、定时刷新、数量上限
- **输入**: 蝙蝠/哥布林 prefab, 刷新点位置, 场景引用
- **输出**: EnemySpawner.cs
- **验证**: 怪物定时刷新、数量上限、位置正确

### 7. TreasureChest (demoForest_049)
- **职责**: 宝箱交互（靠近按 E 开启，掉落奖励，播放动画和 VFX）
- **输入**: 宝箱 prefab, 开箱动画, 金色光柱 VFX, 奖励音效
- **输出**: TreasureChest.cs, ChestReward.cs
- **验证**: 靠近显示提示、按 E 开启、动画+VFX+奖励

### 8. HealthSystem (demoForest_050)
- **职责**: 玩家和敌人生命值管理、受击减血、死亡判定
- **输入**: 角色 prefab, 受击动画, 死亡动画, UI 血条引用
- **输出**: HealthSystem.cs, DamageInfo.cs
- **验证**: 受击减血、血条更新、死亡触发

### 9. AdventureCameraController (demoForest_051)
- **职责**: 第三人称跟随摄像机，瞄准时拉近越肩视角
- **输入**: 摄像机对象, 玩家引用, 瞄准状态
- **输出**: AdventureCameraController.cs
- **验证**: 摄像机平滑跟随、瞄准时视角拉近

## 验证流程

每个机制类生成后，Agent 执行以下验证：

1. **compile_success** — 代码编译无错误
2. **功能验证** — 通过 run_playmode + screenshot + read_log 验证功能
3. **修复循环** — 若验证失败，Agent 读取错误日志、修改代码、重新编译（最多 3 次）
