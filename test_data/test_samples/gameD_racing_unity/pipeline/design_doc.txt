# Game Design Brief - gameD_racing_unity MVP

## Concept

A compact arcade circuit-racing demo assembled in Unity from a prepared racing
car, one rigged driver and a prepared environment-only track package. The first
version validates asset import, generated mechanic/UI code and Play Mode. CG,
generated audio, WebGL and browser serving are deferred.

## Core Loop

```
Launch -> 3-2-1-GO -> Race -> Ordered Checkpoints -> Complete 3 Laps
-> Finish and Rank -> Restart
```

## Racers

The player and three AI opponents reuse the same imported car and driver
prefabs. Material variants may distinguish AI cars. The generated mechanic
builds Rigidbody vehicle rigs around the imported visuals and creates a seated
driver pose without external motion clips.

## Scene

The cleaned track environment retains rendering, lighting and static collision
but no original gameplay, kart, camera or UI components. Generated metadata
adds four clear grid positions, ordered checkpoints and a closed AI racing line.

## Mechanic and UI

Mechanic and UI are separate Unity packages. Mechanic owns physics, AI, race
state, timing, cameras and runtime-session state. UI consumes its public state,
events and commands for the HUD, countdown and results screen.

## Controls

| Action | Key |
|---|---|
| Accelerate | W |
| Brake / reverse | S |
| Steer | A / D |
| Handbrake | Space |
| Camera | C |
| Restart | Enter |

## Delivery

All prepared assets are first materialized under
`test_data/outputs/gameD_racing_unity/<run_id>/`. Codely generates the mechanic and UI
task artifacts. UnityClient then creates or opens the generated project,
imports artifacts, installs both packages, composes the scene, compiles and
enters Play Mode for iterative debugging.
